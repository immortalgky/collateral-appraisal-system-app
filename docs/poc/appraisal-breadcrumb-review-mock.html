Breadcrumb ใบประเมิน: ตอนนี้ vs ที่เสนอ

ไล่ทุกหน้าใต้ /tasks/:taskId/* และ /appraisals/:appraisalId/* ช่อง "ตอนนี้" คำนวณตามโค้ดใน TaskLayout / AppraisalLayout จริง ๆ (รวมข้อความที่หน้าเติมผ่าน useBreadcrumbExtras) เลขใบประเมินและชื่อรายการเป็นตัวอย่าง

หน้าตอนนี้เสนอปัญหา

ต้นเหตุ

  • ป้ายฝังเป็นอังกฤษในโค้ด 2 ชุด — ตาราง routeLabels ก๊อปไว้ทั้งใน TaskLayout และ AppraisalLayout แล้วเริ่มไม่ตรงกัน — TaskLayout ไม่มี activity-tracking ทั้งที่งานก็มีหน้านี้ (AppraisalLayout มี)
  • ไม่ได้ใช้ชื่อเดียวกับที่ผู้ใช้กด — เมนูข้างอ่านชื่อจาก DB, แท็บอ่านจาก i18n แต่ breadcrumb มีคำของตัวเอง
  • รู้จักแค่ URL ที่อยู่ในตาราง — หน้าใหม่ (สรุปเครื่องจักร, ใบเสนอราคา, 360, สิทธิการเช่า, เครื่องจักร) ไม่มีใครเพิ่มเข้าตาราง breadcrumb เลยหยุดกลางทาง
  • หน้าแก้ไขไม่บอกว่าแก้อะไร — มีแค่ตลาด/กฎหมาย/แบบ/อาคาร (block) ที่เติมชื่อรายการ ทรัพย์สิน 9 ประเภทกับการวิเคราะห์ราคาไม่เติม

ทำอย่างไร

  1. ตัวสร้างชุดเดียว buildAppraisalBreadcrumb() ใช้ทั้งสอง layout ต่างกันแค่ crumb แรก
  2. ระดับหน้า = ชื่อเมนูข้าง จับจาก path ใน useMenuStore.appraisal + resolveLabel — ตรงกับเมนูเสมอ admin แปลได้เอง
  3. ระดับแท็บ = คีย์ i18n ตัวเดียวกับแถบแท็บ และใส่เสมอ ถ้า URL ไม่มี ?tab= ใช้แท็บแรก
  4. ชื่อรายการ — PropertyEditorHeader เติมชื่อทรัพย์ครั้งเดียวได้ทั้ง 9 หน้า (หาแถวทรัพย์อยู่แล้ว) · หน้าวิเคราะห์ราคาเติมชื่อกลุ่ม/แบบ
  5. เพิ่ม route ที่หายไป ตามตาราง และ "New Markets" → "เพิ่มข้อมูลตลาด"
  6. crumb แรกของโหมดดูใบประเมิน ตั้งชื่อตามหน้าที่มาจริง (มี returnPath อยู่แล้ว)

อยากให้ตัดสินใจ

  • ระดับหน้าเอาจากเมนู DB หรือ i18n ในโค้ด? — DB: ตรงกับเมนูข้างเสมอ แต่ตอนนี้คำแปล th ของเมนูใบประเมินทั้ง 17 รายการเป็นคำอังกฤษ (ต้องให้ admin แปลในหน้าจัดการเมนู) · i18n: ไทยทันที แต่ถ้า admin เปลี่ยนชื่อเมนู breadcrumb ไม่เปลี่ยนตาม
  • หน้าแก้ทรัพย์ใส่ระดับแท็บ "ทรัพย์สิน" คั่นก่อนชื่อทรัพย์ไหม? (ตารางใส่ไว้)
  • ชื่อรายการยาวมาก ให้ตัดท้ายด้วย … และขึ้นเต็มตอนชี้ไหม
